# Memory Draft 顶层设计

## 背景

当前 Memory 直接从离散对话中提取。不同类别的 Memory 会分别读取各自的消息窗口，再独立完成事件还原、实体识别、指代判断、长期价值判断、分类和证据选择。

在使用低成本、能力有限的模型时，这种一次承担多项工作的方式容易产生以下问题：

- 连续事件被拆散，批次边界前后的信息难以衔接；
- 人物、角色、地点和重要概念被混淆或过度抽象；
- 同一内容被重复写入多个 Memory 类别；
- 条目归属错误、原子性不足，短期信息混入长期档案；
- 模型需要从大量离散消息中同时总结内容并选择精确证据，任务负担过重。

本次重构引入 Draft 中间层，核心目标不是建立更精密的语义系统，而是把复杂任务拆成多个适合低能力模型完成的简单任务。

## 核心思路

整体信息流调整为：

```text
原始对话
  → 实体识别
  → 连贯、详细的 Draft
  → 各类别 Memory
```

原始消息仍然是最终来源和重建依据，但 Memory 不再直接从离散消息中总结，而是从已经恢复了上下文连续性的 Draft 中提取。

Draft 是自然语言形式的叙事缓冲层，不承担知识图谱、精确事实建模或细粒度证据标注职责。

## 设计原则

### 1. 降低单次 LLM 任务难度

Draft 生成分为两个简单阶段：

1. 先识别当前内容涉及的主要人物、对象、地点和重要概念；
2. 再以实体列表作为注意力提示，将对应对话整理为连贯、详细的自然语言 Draft。

实体识别只用于减少主体混淆和宽泛概括，不要求建立全局实体 ID、复杂类型系统或精确的跨批次实体消歧。

### 2. Draft 保持详细和连贯

Draft 应保留理解后续对话所需的主体、事件过程、变化、纠正、时间线索和未决事项，避免过早压缩成高度抽象的长期结论。

Draft 负责回答“这段对话连贯地发生了什么”，Memory 再负责判断“哪些内容值得以何种形式长期保留”。

### 3. 允许重写 Draft 尾部

Draft 的尾部可以在收到新消息后重新总结，使跨批次事件能够形成完整叙述，避免在事件尚未结束时留下割裂摘要。

尾部 Draft 在开放期间可以更新；封存后保持不变。Memory 只消费已经封存的 Draft，不依赖仍可能变化的尾部内容。

### 4. 使用粗粒度 Evidence

每个 Draft 对应一个连续的原始消息区间。Memory 的 evidence 记录 Draft ID，由 Draft 间接映射到原始消息区间。

模型只需要从少量可见 Draft 中选择 evidence，不再负责精确选择具体 message ID。程序负责保证 Draft ID、消息区间和处理边界的有效性。

对于后续修正，新的 Draft ID 可以追加为修正来源，从而保留事实形成和被纠正的历史轨迹。

### 5. 明确来源层级

- 原始消息是最终来源，负责删除、隐私处理和完整重建；
- Draft 是可重建的派生叙事层；
- Memory 是从 Draft 中提取的长期和工作记忆层；
- Draft 与 Memory 都不能取代原始消息的来源地位。

### 6. 用程序保证边界，用 LLM 处理语义

消息区间、Draft 顺序、处理 cursor、状态转换和重建边界由确定性代码维护。

LLM 只负责：

- 找出主要实体；
- 生成或更新连贯 Draft；
- 从 Draft 中提取 Memory。

不要求 LLM 精确维护消息映射、实体数据库或复杂的内部状态。

## 增量处理

正常运行时，Draft 按消息顺序持续推进：

1. 新消息达到触发条件后进入当前开放尾部；
2. 模型根据实体列表、尾部相关内容和新消息更新 Draft；
3. Draft 达到适当边界后封存；
4. 各 Memory 类别按自己的进度消费新的已封存 Draft；
5. 尚未封存的最近对话仍由普通聊天上下文覆盖。

Draft 和各类 Memory 分别维护自己的处理进度，避免某个 Memory 类别阻塞 Draft 或其他类别。

## Rebuild

重建采用明确的两阶段流程：

```text
冻结原始消息边界
  → Draft 按完整区间逐段推进至该边界
  → 校验 Draft 覆盖连续
  → Memory 从 Draft 起点逐段推进
  → 所有 Memory 类别到达最新 Draft
  → 完成重建
```

Memory 重建期间只消费本次 Draft generation 的内容，避免混用不同重建批次的 Draft。

任何原始消息删除、修改或隐私操作，都应从受影响位置重新生成 Draft，并据此重建下游 Memory。

## 质量目标

重构完成后重点观察：

- Draft 是否能完整、连贯地恢复事件；
- 主要人物和对象是否保持清晰；
- Memory 中跨类别重复和归属错误是否减少；
- 长期条目的原子性和稳定性是否提高；
- 当前状态、历史事件与长期档案是否更少混淆；
- rebuild 是否能够稳定得到覆盖完整的 Draft 和 Memory；
- 在低成本模型下，质量提升是否足以覆盖新增 Draft 调用成本。

## 非目标

本设计不追求：

- 将 Draft 建设为知识图谱或结构化事实数据库；
- 让模型精确输出每条结论对应的 message ID；
- 建立 claim 级别的复杂 evidence 系统；
- 依赖高能力模型完成精细实体消歧和逻辑推理；
- 让 Draft 直接承担最终 Memory 的分类职责；
- 通过增加复杂 schema 来约束出理想化的语义结果。

Draft 的价值在于提供连贯、详细、主体明确的中间内容，以任务拆分降低低能力模型生成 Memory 时的认知负担。
